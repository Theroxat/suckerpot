# M26 — Report outcomes: did anyone answer?

Status: proposal for review. Builds on M22 (reports), M25 (send queue and SMTP). Default behaviour
is unchanged: no mailbox is contacted until the owner sets `ABUSE_REPLIES_ENABLED=true` **and**
saves and enables a mailbox in Settings. Without a mailbox, everything else in this milestone works:
the owner can paste a reply (or upload an `.eml`), set an outcome by hand, and the Results page shows
what was sent. Every address, mailbox and name below is a placeholder (documentation ranges,
`example.org`, `example.net`, documentation ASNs AS64496 to AS64511).

## 1. Goal and invariants

The owner wants to see how many reports were sent (per provider, ASN, country, over time), whether
anyone answered, what kind of answer it was, and how long it took.

| # | Invariant | Enforced by |
| --- | --- | --- |
| O1 | The mailbox is reached only through the VPN proxy. The gate is checked before any socket exists; with the gate closed nothing is attempted. | `suckerpot_egress.TunnelIMAP4` / `TunnelIMAP4_SSL` (§4.1), `ingest/tests/test_egress_static.py` (imaplib clients forbidden elsewhere) |
| O2 | Mail is never deleted, written or answered. The only changes are `\Seen` or `UID MOVE` to a folder. No `\Deleted`, `EXPUNGE`, `APPEND`, `DELETE`, `RENAME`, no SMTP from the replies package. | `SafeMailbox` wrapper (§4.2), `ingest/tests/test_replies_static.py` |
| O3 | Incoming mail is hostile. Sizes are capped, only headers and a bounded partial body are fetched, parsing is stdlib `email` with `compat32` on bounded bytes, attachments are never decoded or opened, HTML is never rendered (tags stripped to text when there is no text part), no link is followed or made clickable. | §5 |
| O4 | Mail unrelated to a report is never stored and never flagged. The body is fetched only after the headers show a link to a report or a delivery status notification (DSN). | §4.3 |
| O5 | Only metadata and a bounded plain-text excerpt (≤ 2,000 characters) are stored. Excerpts are deleted after `ABUSE_REPLY_EXCERPT_DAYS`. | §9, §13 |
| O6 | The reply token is random and opaque. It is independent of every internal id and appears only in the outgoing Subject (and, if chosen, one body line). It is never in X-ARF, CSV, STIX, MISP, file names or the Message-ID. | §2, guard tests §15 |
| O7 | A reply changes a report's outcome automatically only when it is verified: matched by our own Message-ID, or authenticated (DKIM/DMARC pass) from the recipient's domain. Anything else waits for the owner. | §7.3 |
| O8 | Off by default: `ABUSE_REPLIES_ENABLED=false`, and `report_imap.enabled=false` even when a profile exists. | `ingest.features`, §3 |

## 2. The reply token

### 2.1 Generation

`abuse_reports.reply_token text NOT NULL UNIQUE`, default
`left(replace(gen_random_uuid()::text, '-', ''), 12)`, `CHECK (reply_token ~ '^[0-9a-f]{12}$')`.
The first 12 hex digits of a v4 UUID are random (48 bits, from `pg_strong_random`). Existing rows are
backfilled by the default when the column is added. The token is not derived from `id`, `public_id`
or `id_seed`. `suckerpot_reporting.ids.new_reply_token()` (`secrets.token_hex(6)`) exists for tests
and for any code path that inserts the column explicitly. The transition trigger adds `reply_token`
to the immutable identity columns.

### 2.2 Where it appears

`report_settings.reference_style` (`subject` default, `subject_and_body`, `off`), set in
Settings > Reporting:

- The subject template gains a `{ref}` placeholder. If the template has no `{ref}` and the style is not
  `off`, the renderer appends ` (ref 3f9a1c7b2e4d)` to the subject.
- `subject_and_body` also adds a last body line `Ref: 3f9a1c7b2e4d`.
- Never in the X-ARF YAML part, `evidence.csv`, STIX, MISP, `.eml` file names or download names.

The SMTP `Message-ID` stays `<token_urlsafe(18)@sender-domain>` (M25), unrelated to `reply_token`.
Ingest now stores it in `abuse_send_requests.message_id` when it claims the request (status
`sending`), before connecting. Manual sends (send queue, `mailto:`) have no Message-ID we know of:
the subject token is their matching key.

### 2.3 What it reveals

48 random bits, one per report: nothing about the owner, the monitored system or the project. The
shape `(ref <12 hex>)` is a common ticket-reference shape; the residual fingerprint risk (the format
is in this public repo) is stated in Settings, and the owner can move it (`{ref}` anywhere in the
template) or turn it off (`off` keeps Message-ID matching for SMTP sends only).

### 2.4 Guard changes (`reporting/`)

- `GuardContext.internal_ids` also receives `id_seed.hex` (32 chars) from ingest
  (`ingest/ingest/abuse/build.py`, `reportmail/sender.py`) and the API (`abuse_core.guard_context`):
  the seed must never leave, and a token accidentally built from it is caught.
- `message_subject()` and `render_text()` take `reply_token: str | None` and `reference_style`.
  `render_xarf()` passes the token to the human part only; `render_csv`, `stix`, `misp` never receive it.
- No new reason code. A token never matches existing codes because it is 12 hex characters and the
  shortest internal id (session id, UUID) is longer.

## 3. Mailbox profile (Settings > Reporting > Replies)

One profile in table `report_imap` (single row, migration 0026). Same pattern as `report_smtp`:

- Columns: `enabled` (default false), `host`, `port`, `security` (`ssl` default port 993, `starttls`
  port 143; no plain-text option), `username`, `password` (AES-GCM with the existing `SecretBox`,
  AAD `report_imap`, never returned; `password_set` generated column), `folder` (default `INBOX`),
  `processed_action` (`mark_read` default, `move`), `move_folder`, `poll_minutes` (5 to 1440, default
  15), `since` (date; mail with an earlier INTERNALDATE is ignored; defaults to the day the profile is
  first saved), `updated_at`, `updated_by`.
- `host` must pass `api.abuse_smtp.valid_host` (a public DNS name, no IP literal, no internal suffix).
  `folder` and `move_folder`: printable ASCII, 1 to 100 chars, no `"`, `\`, `*`, `%`, CR or LF (always
  sent quoted). `move_folder` must differ from `folder`.
- Write routes are admin-only, CSRF, and ask for the account password again. `GET` is admin-only too
  (it holds the owner's mailbox) and returns everything but the password.
- Recommended in the UI: a dedicated mailbox or alias for reports. The reply contact of M22 is where
  replies arrive; the profile should read that mailbox.
- Proton: IMAP needs Proton Bridge, which is not part of the stack (open question 1). The card says so.
- Nothing in the profile goes through the identity guard: it is sent only to the owner's own mail
  provider, through the tunnel. The client never sends the IMAP `ID` command.

Ingest keeps its own state in `report_imap_state` (single row): `profile_fingerprint`
(sha256 of `host|port|username|folder`), `uidvalidity`, `last_uid`, `move_supported`, `last_poll_at`,
`last_ok_at`, `last_error`, `counters` (today's `fetched`, `relevant`, `matched`, `ignored`,
`oversize`). When the fingerprint changes (another mailbox or folder), ingest resets `uidvalidity`
and `last_uid`.

"Test connection" and "Check now" are rows in `report_imap_requests` (`kind`: `test` | `poll`), the
API-asks-ingest-does pattern of `abuse_send_requests`.

## 4. Polling worker (`ingest/ingest/replies/`, flag `ABUSE_REPLIES_ENABLED`)

### 4.1 Egress adapter (`egress/suckerpot_egress/imap.py`, new)

```python
class TunnelIMAP4(imaplib.IMAP4):           # plain IMAP; STARTTLS is mandatory before LOGIN
    def __init__(self, gate: EgressGate, host: str, port: int, *, timeout: float) -> None
    def _create_socket(self, timeout: float | None) -> socket.socket
        # open_tunnel_sync(self._gate, self.host, self.port, timeout=timeout or 15.0)

class TunnelIMAP4_SSL(imaplib.IMAP4_SSL):   # implicit TLS; certificate and host name verified
    def __init__(self, gate: EgressGate, host: str, port: int, *,
                 ssl_context: ssl.SSLContext, timeout: float) -> None
    def _create_socket(self, timeout: float | None) -> socket.socket
        # raw = open_tunnel_sync(...); return self.ssl_context.wrap_socket(raw, server_hostname=self.host)
```

Exported from `suckerpot_egress/__init__.py`. The module lowers `imaplib._MAXLINE` to 65,536 (process
wide; only ingest imports imaplib). `debug` stays 0: server answers are never logged.

`ingest/tests/test_egress_static.py`: add `imaplib.IMAP4`, `imaplib.IMAP4_SSL`, `poplib.POP3`,
`poplib.POP3_SSL` to `FORBIDDEN_CALLS` and `imaplib`, `poplib` to `FORBIDDEN_MODULES` (the replies
package imports `TunnelIMAP4*` from `suckerpot_egress`, never `imaplib` clients itself; it may import
`imaplib.Internaldate2tuple` through a helper in `suckerpot_egress.imap`, so the replies package has no
`imaplib` import at all).

### 4.2 `SafeMailbox` (`ingest/ingest/replies/imap.py`)

A thin wrapper that owns the private imaplib object and exposes only:

| Method | IMAP | Notes |
| --- | --- | --- |
| `connect()` | TCP via tunnel, TLS or `STARTTLS`, `CAPABILITY` | `STARTTLS` missing → `tls_failed`; never `LOGIN` in clear |
| `login()` | `LOGIN` | password from the decrypted profile, never logged |
| `select(folder, readonly)` | `SELECT` / `EXAMINE` | returns `UIDVALIDITY`, `EXISTS`; `EXAMINE` for tests |
| `search_new(last_uid, since)` | `UID SEARCH UID n:* SINCE dd-Mon-yyyy` | never `UNSEEN`: the owner may have read mail already |
| `fetch_headers(uids)` | `UID FETCH … (UID RFC822.SIZE INTERNALDATE BODY.PEEK[HEADER.FIELDS (…)])` | batches of 25 |
| `fetch_partial(uid, n)` | `UID FETCH uid (BODY.PEEK[]<0.n>)` | `.PEEK`: fetching never sets `\Seen` |
| `mark_seen(uid)` | `UID STORE uid +FLAGS.SILENT (\Seen)` | the only flag ever written |
| `move(uid, folder)` | `UID MOVE` (RFC 6851) | only when `MOVE` is in the capabilities; else falls back to `mark_seen` and records `move_supported=false` |
| `list_folders()` | `LIST "" "*"` | test only; ≤ 50 names, sanitised |
| `logout()` | `LOGOUT` | always, in `finally` |

Header fields fetched: `FROM SUBJECT DATE MESSAGE-ID IN-REPLY-TO REFERENCES AUTO-SUBMITTED PRECEDENCE
X-AUTOREPLY X-AUTORESPOND CONTENT-TYPE AUTHENTICATION-RESULTS RETURN-PATH`.

Blocking imaplib runs in `asyncio.to_thread`, with the same deadline technique as
`reportmail.outgoing.deliver`: socket timeouts of `min(15 s, time left)` and a timer that shuts the socket
down after `ABUSE_REPLY_POLL_DEADLINE_S` (120 s) per poll.

### 4.3 One poll

1. Load the profile. If none, `enabled=false`, or the password cannot be decrypted, publish status
   `not_configured` / `paused` and stop.
2. `gate_open()` false → status `egress_closed`, nothing attempted (no row, no socket).
3. Connect, log in, `SELECT folder`. On a `UIDVALIDITY` change: `last_uid = 0`. The `since` date and the
   unique `(source, uidvalidity, uid)` and `message_id_sha256` keys prevent re-processing.
4. `search_new` → at most `ABUSE_REPLY_MAX_PER_POLL` (50) UIDs, oldest first, and at most
   `ABUSE_REPLY_DAILY_CAP` (500) per UTC day. Any extra mail waits for the next poll.
5. `fetch_headers`. A header block larger than 64 KiB is skipped as `oversize`. **Relevance from
   headers only** (§7.1 steps 1, 2 and 5, plus "looks like a DSN": `Content-Type: multipart/report`,
   or a From local part of `mailer-daemon` / `postmaster`). Not relevant → nothing stored, flags
   untouched, `last_uid` advances, counter `ignored`.
6. Relevant: check `RFC822.SIZE`. If it is above `ABUSE_REPLY_MAX_BYTES` (256 KiB), fetch only the first
   `ABUSE_REPLY_MAX_BYTES` and set `truncated=true`. Parse (§5), classify (§6), match (§7), store
   (`abuse_replies`), and update the outcome (§8). All of this happens in one DB transaction per message.
7. After the commit: `mark_seen` or `move`, according to the profile. If the flag or move fails,
   only `last_error` is set; the stored reply stays.
8. Commit `last_uid`, `last_poll_at`, counters. Logout.

Pasted replies (`abuse_reply_imports`, §11) are processed in the same worker cycle, without IMAP:
same parser, classifier and matcher, `source='paste'`. The raw bytes are then cleared
(`raw = ''::bytea`, `status = 'done'`). This works with no mailbox configured.

Error codes (`report_imap_state.last_error`, `report_imap_requests.error_code`): `not_configured`,
`paused`, `egress_closed`, `tls_failed`, `auth_failed`, `no_folder`, `no_move_folder`, `timeout`,
`network`, `protocol`, `internal`. Server answers are never stored.

## 5. Parsing hostile mail (`ingest/ingest/replies/parse.py`, pure)

Input is at most `ABUSE_REPLY_MAX_BYTES` of raw message. Output is a frozen `ParsedReply` dataclass.

| Step | Rule |
| --- | --- |
| Parser | `email.parser.BytesParser(policy=email.policy.compat32).parsebytes(raw)`: legacy policy, no structured header objects |
| Headers | ≤ 200 header lines considered; each value cut at 4 KiB before decoding; `email.header.decode_header` in `try`, charset allowlist (below), errors replaced |
| MIME walk | Iterative, ≤ 50 parts, depth ≤ 5; stop silently beyond |
| Decoded parts | Only `text/plain`, `text/html`, `message/delivery-status`, `text/rfc822-headers` / `message/rfc822-headers`, and the header block of a `message/rfc822` part. Each decoded payload is capped at 128 KiB |
| Attachments | Never decoded. Metadata only: `{"count", "types": [≤ 10 content types], "bytes"}`. File names are not stored |
| Charsets | `utf-8`, `us-ascii`, `iso-8859-1..15`, `windows-1250..1258`, `koi8-r`, `gb2312`, `gbk`, `gb18030`, `big5`, `shift_jis`, `euc-jp`, `iso-2022-jp`, `euc-kr`; anything else is decoded as UTF-8 with `errors="replace"` |
| HTML | Used only when there is no `text/plain` part: a `html.parser.HTMLParser` subclass keeps text outside `script`/`style`, ≤ 128 KiB input. Never rendered, no URL kept as a link |
| DSN | `message/delivery-status`: `Action`, `Status` (`^[245]\.\d{1,3}\.\d{1,3}$`), `Final-Recipient` (domain only). Original `Message-ID` and `Subject` read from the returned headers part |
| From | `email.utils.parseaddr`, ASCII mailbox regex as in `outgoing._MAILBOX`; domain lower-cased; else `from_address = NULL` |
| Auth | The **topmost** `Authentication-Results` header only (the owner's provider adds it first): `dmarc=pass header.from=<d>`, `dkim=pass header.d=<d>`. `auth = pass` when aligned with the From domain (equal or a subdomain), `fail` on `dmarc=fail`, else `none` |
| Excerpt | Text body → drop lines starting with `>`; cut at the first line that is `-----Original Message-----`, ends with `wrote:`, or starts with `From:` after a blank line; NFKC; remove C0/C1 controls (except `\n`, `\t`), zero-width and bidi characters; collapse blank runs; cut at `ABUSE_REPLY_EXCERPT_CHARS` (2,000). Unicode is kept (non-English desks) |
| Subject | Decoded, controls removed, ≤ 300 chars |
| Message-ID | Stored only as `sha256(lower(value))` for dedupe |

All of this runs in `asyncio.to_thread`. The bounded input and structure keep the parse linear. Fuzz
tests (§15) prove each limit.

## 6. Classification rules (`ingest/rules/replies/*.yaml`)

### 6.1 Engine

Condition nodes reuse the tagging grammar (`all`, `any`, `not`, leaf operators `equals`, `in`,
`contains`, `contains_any`, `startswith`, `endswith`, `glob`, `exists`, `gte`, `lte`). There are no
regular expressions, so a rule cannot backtrack. The engine change is
`compile_condition(raw, where, *, fields: frozenset[str] | None = None)`: when `fields` is given, it
replaces the event/session whitelist. It also gets a public `evaluate(cond, get) -> bool`. Existing
callers are unchanged.

Fields (whitelist `REPLY_FIELDS`): `from_address`, `from_domain`, `from_local`, `subject`, `body`
(the decoded text, ≤ 8 KiB considered), `auto_submitted`, `precedence`, `x_autoreply`,
`x_autorespond`, `content_type`, `report_type`, `dsn_action`, `dsn_status`, `has_in_reply_to`,
`attachment_count`, `matched` (bool).

### 6.2 File format

```yaml
# ingest/rules/replies/20-resolved.yaml
rules:
  - id: resolved-action-taken
    outcome: resolved              # auto_ack | ticket_opened | resolved | rejected | bounce | human_reply | unknown
    priority: 20                   # lower runs first; first match wins
    description: The provider says it acted (suspended, terminated, removed, null-routed).
    when:
      any:
        - {field: body, contains_any: ["has been suspended", "has been terminated", "we have taken action",
                                       "action has been taken", "has been removed", "null-routed",
                                       "the server has been shut down", "issue has been resolved"]}
        - {field: subject, contains_any: ["resolved", "closed - action taken"]}
tickets:                           # ticket id extraction, linear scan, no regex
  - id: generic-ticket
    after: ["ticket #", "ticket#", "ticket:", "ticket id:", "case #", "case:", "incident #",
            "[#", "reference:", "ref#", "ticket number"]
    fields: [subject, body]
    min_len: 4
    max_len: 32
    chars: "A-Za-z0-9-_"            # charset of the id; a run must contain at least one digit
```

The loader (`ingest/ingest/replies/rules.py`) refuses unknown keys and outcomes, duplicate ids,
`priority` outside 1 to 999, and more than 200 rules. It fails the worker start, not a poll.

### 6.3 Default rules shipped (generic, no real address)

| File | Outcome | Signals (all case-insensitive, substring) |
| --- | --- | --- |
| `10-bounce.yaml` | `bounce` | `report_type: delivery-status` with `dsn_action: failed`; From local part `mailer-daemon`/`postmaster` with subject `undeliver`, `delivery status notification`, `returned mail`, `mail delivery failed` |
| `20-resolved.yaml` | `resolved` | as in §6.2, plus `customer has been notified and`/`service was terminated`/`content was removed` |
| `30-rejected.yaml` | `rejected` | `not our customer`, `not within our network`, `does not belong to`, `we do not host`, `not hosted by`, `please contact the`, `outside our jurisdiction`, `insufficient evidence`, `unable to act`, `please use our web form`, `submit via our portal` (rule id `form-required`) |
| `40-ticket.yaml` | `ticket_opened` | a ticket id was extracted **and** (`auto_submitted` starts with `auto-` or the body contains `ticket has been created`, `case has been opened`, `we have received your report`) |
| `50-auto-ack.yaml` | `auto_ack` | `auto_submitted` `auto-replied`/`auto-generated`; `x_autoreply` exists; `precedence` in `auto_reply`, `bulk`, `junk`; subject `automatic reply`, `auto-reply`, `autoreply`, `out of office`; body `this is an automated`, `do not reply to this`; DE `automatische antwort`, FR `réponse automatique`, ES `respuesta automática`, NL `automatisch antwoord`, PT `resposta automática` |
| fallback (code) | `human_reply` | no rule matched, no auto header, `from_domain` set, body text ≥ 20 chars |
| fallback (code) | `unknown` | anything else |

Ordering is bounce, resolved, rejected, ticket, auto-ack. An auto-acknowledgement that carries a
ticket number is `ticket_opened`. A human answer that says "terminated" is `resolved`.

## 7. Matching a reply to a report (`ingest/ingest/replies/match.py`)

### 7.1 Order (first hit wins)

| # | Method (`match_method`) | How |
| --- | --- | --- |
| 1 | `message_id` | Any id in `In-Reply-To` / `References` (≤ 20 ids, each ≤ 255 chars) equals an `abuse_send_requests.message_id` with `status = 'sent'` |
| 2 | `token` | A 12-hex word found right after `ref` / `ref:` / `ref#` / `(ref` in the Subject, or in the body (first 8 KiB), equals an `abuse_reports.reply_token` |
| 3 | `dsn` | For a DSN, steps 1 and 2 run on the returned original headers (`Message-ID`, `Subject`) |
| 4 | `ticket` | The extracted ticket id equals the `ticket_id` of an earlier reply already linked to a report, from the same `from_domain` |
| 5 | `sender_domain` | `from_domain` equals the registrable domain of the recipient mailbox, override mailbox or a `reply_domains` entry of **exactly one** report sent in the last `ABUSE_REPLY_MATCH_DAYS` (120). More than one → unmatched |
| — | `none` | Stored only if it is a DSN or from a known recipient domain (shown under "Replies to check"); otherwise not stored at all (O4) |

The token is looked up among reports with status `sent` or `closed`. A token that matches a report in
another status is treated as `none`.

### 7.2 Recipient reply domains

`abuse_recipients.reply_domains text[]` (≤ 5). Ticket systems often answer from another domain
(`tickets.example.org` for `abuse@example.net`). The owner adds one when confirming a reply ("Trust
this domain for this provider").

### 7.3 Verification (O7)

`verified = true` when:

- `match_method = 'message_id'` (or `dsn` through a Message-ID); or
- `auth = 'pass'` and `from_domain` (registrable) equals the recipient's mailbox domain, override
  domain or one of its `reply_domains`; or
- the owner confirmed it (`PATCH`, §11).

Unverified replies are stored and shown, but do not change `auto_outcome`. The report's outcome row
gets `needs_review = true`. This covers the case where an attacker who received a forwarded report
writes "resolved" to the reply address.

## 8. Outcomes (`abuse_report_outcomes`)

One row per report with status `sent` or `closed`. Ingest creates it (`auto_outcome = 'none'`) on its
first cycle after the report is sent.

| Column group | Writer | Meaning |
| --- | --- | --- |
| `auto_outcome`, `reply_count`, `first_reply_at`, `first_human_at`, `ticket_at`, `resolved_at`, `rejected_at`, `bounced_at`, `ticket_id`, `needs_review`, `auto_updated_at` | ingest | Derived from verified replies |
| `manual_outcome`, `manual_at`, `manual_by`, `note` | API | Owner override; `manual_at` is when it happened (default now, may be earlier, not before `sent_at`) |

Effective outcome is `COALESCE(manual_outcome, auto_outcome)`. Derivation (pure function
`outcome.derive(replies) -> AutoOutcome`, verified replies only) uses this precedence:
`resolved` > `rejected` > `ticket_opened` > `human_reply` > `auto_ack` > `bounce` > `unknown` > `none`.
Delays are measured from `abuse_reports.sent_at`.

- **No answer** is not stored. The API reports it for `outcome = 'none'` and
  `sent_at < now() - ABUSE_NO_ANSWER_DAYS` (14).
- A bounce also sets `needs_review`, and the report page suggests an override mailbox for the
  recipient.
- Reports are not closed automatically: closing stays a decision of the owner.

Triggers and functions:

- `abuse_reports_transition`: copy of the 0022 function with `OR NEW.reply_token <> OLD.reply_token`
  added to the immutable identity check. Downgrade restores the 0022 body.
- `abuse_send_requests_guard`: copy of 0022 plus two rules. The API may not insert a `message_id`.
  `message_id` changes only from NULL, by ingest, in the update that sets `status = 'sending'`, and is
  immutable afterwards.
- `abuse_report_outcomes_guard` (BEFORE INSERT OR UPDATE): the report must be `sent` or `closed`.
  `manual_at` may not be before `abuse_reports.sent_at`.
- `suckerpot_abuse_prune` (replace):
  - delete `abuse_send_requests` older than 30 days only when `kind = 'test'` or `status <> 'sent'`
    (sent `send` rows go with their report);
  - set `excerpt = NULL, excerpt_purged_at = now()` on replies older than `excerpt_days` (config key,
    default 180);
  - delete unmatched replies older than 180 days;
  - delete `abuse_reply_imports` that are done and older than 7 days;
  - delete `report_imap_requests` that are done and older than 30 days.

  `suckerpot_db.retention` passes `excerpt_days` from `ABUSE_REPLY_EXCERPT_DAYS`.

## 14. Retention

Reply metadata lives as long as its report: sent reports are kept for `ABUSE_REPORT_RETENTION_DAYS`
(730), and their replies and outcome rows are deleted with them (cascade). Excerpts are cleared after
180 days. Unmatched replies are deleted after 180 days. Pasted raw mail is cleared right after
processing. M27's monthly roll-up keeps the aggregates after reports expire.

## 18. Risks and open questions

1. **Proton**: IMAP needs Proton Bridge. A Bridge container would be a new service with its own
   egress question. Out of scope; the paste path covers Proton users.
2. **Mailbox not dedicated**: the header-first relevance check keeps unrelated mail out of the
   database. The owner should still use an alias that only receives replies.
3. **Authentication-Results trust**: only the topmost header is read. If the owner's provider does not
   add one, nothing is auto-verified except Message-ID matches. The owner confirms by hand.
4. **Token shape fingerprint**: public format, random value. Accepted; can be moved or turned off.
5. **Auto-close**: proposed **no**. A `resolved` outcome does not close the report; the owner closes it.

## Review hardening (integration)

Decisions taken after the security review of the merged M26/M27 branch:

- **A bad mail never stops the mailbox.** A mail whose own data breaks a constraint is counted
  (`counters.failed`) and skipped; the position (`last_uid`) always moves past it. Only a broken
  connection or database stops a poll without moving it. Every stored field is clamped to its
  column in `parse.py` (sender address 254, domain 253, attachment types ASCII, at most 64
  characters, attachments JSON at most 2048 bytes).
- **Authentication-Results is only read from the owner's own server.** `report_imap.trusted_authserv_id`
  (Settings, optional) names the authserv-id the mailbox provider writes. Only the first header
  with that id counts; without it `auth` is always `none`. Clauses are split outside quoted
  strings and comments.
- **Quoting our Message-ID verifies nothing by itself.** A Message-ID match verifies only from a
  party we wrote to; a delivery status notification verifies with `auth = pass` or from such a
  party; every other match needs both.
- **Trust is by exact domain.** A subdomain is another party. Free and shared mail providers
  (`suckerpot_db.shared_mail`) are never trusted by domain, never make a mail relevant and never
  match by sender domain: only the exact address of the recipient's mailbox (or an address the
  owner trusted) counts. The API exposes `shared_mailbox` on the IMAP profile (the owner's own
