# M21 design: anonymous egress, payload collection and static analysis

Status: proposal for review. Scope: `docs/ROADMAP.md`, section M21.
Every address in this document is a placeholder or comes from the documentation ranges
(192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24), except well-known public anycast resolvers used
as probe targets (1.1.1.1, 9.9.9.9).

## 1. Goal and invariants

The owner's home public IP must never be the source of an outbound connection made by the stack.
Today `ingest` sits on the `egress` network and talks to about fifteen external hosts directly. Its
DNS queries are forwarded by Docker's embedded resolver to the host's resolver, so they leave from
the home IP too.

After M21:

| # | Invariant | Enforced by |
| --- | --- | --- |
| I1 | No container except `vpn` is attached to a network that has a route to the internet, apart from the two inbound-only networks that exist today (`sp-ingress` for sensors, `sp-dashboard` for `api`). | Compose layout + static test (§4.1) |
| I2 | `vpn` forwards traffic only through the WireGuard tunnel. With the tunnel down, nothing leaves. | gluetun firewall (kill switch) + host nftables rule (§4.4) |
| I3 | `ingest` and `collector` reach the internet only through the `vpn` HTTP proxy. A client that ignores the proxy fails, because there is no route and no external DNS. | Internal networks only + `dns: 127.0.0.1` + static code test (§3.3) |
| I4 | No egress work starts unless the egress self-check passed in the last `EGRESS_CHECK_INTERVAL_S`. | `EgressGate` in the shared `suckerpot_egress` package (§3.4) |
| I5 | The collector never fetches a private, reserved, documentation, loopback, link-local or own address, and never follows a redirect to one. | URL validator (§5.3) + gluetun DNS rebinding protection + host nftables rule |
| I6 | Fetched files are never executed, never served raw, and are parsed only in a resource-limited child process with no network. | `analyzer` service on an internal network only + child process limits (§6.4) |

Unchanged: sensors answer attackers on the home IP (inbound only, `sp-ingress` has no NEW
outbound, see `scripts/host/firewall.nft`); the dashboard path (cloudflared to `api` on
`sp-dashboard`) is unchanged; host traffic (apt, image pulls, git) is out of scope.

## 2. The `vpn` service

### 2.1 Image choice

**`qmcgaw/gluetun:v3.41.1@sha256:1a5bf4b4820a879cdf8d93d7ef0d2d963af56670c9ebff8981860b6804ebc8ab`**
(index digest checked with `docker pull` on 2026-10-31; Alpine based).

Why gluetun rather than a hand-made `wireguard-go` + iptables image:

- **Userspace WireGuard** (`WIREGUARD_IMPLEMENTATION=userspace`, wireguard-go): the kernel module
  is not loaded on the VM and we do not want to ask the owner to load modules.
- **Kill switch built in**: its firewall (iptables, default DROP) allows only the tunnel interface
  and UDP to the endpoint on the uplink. The firewall is up before the tunnel.
- **DNS server built in**, upstream through the tunnel, with DNS rebinding protection (answers in
  private ranges are dropped). That protection is one of our SSRF layers (§5.3).
- **HTTP proxy built in** with stealth mode (no `Via`, no `X-Forwarded-For`) and basic auth.
- **Control server** with per-route roles, so ingest and the collector can read tunnel status and
  public IP without being able to stop the tunnel.
- It is maintained and pinnable. A home-made image would need the same pieces and more tests.

Rejected: kernel WireGuard (needs the module, `SYS_MODULE` or host change), `network_mode:
service:vpn` for ingest (it would put ingest's DB and Redis traffic inside the VPN container's
namespace and break the "vpn is on no backend network" property), Tor (slow, many APIs block it).

### 2.2 Environment mapping

`vpn/control-auth.toml` (committed, contains no secret):

```toml
[[roles]]
name = "egress-readers"

auth = "none"
```

No role can `PUT /v1/vpn/status`, so a compromised ingest can read the tunnel state but not stop
or reconfigure it. (Stopping it would only close the gate anyway.)

### 2.3 Compose block (contract for task A)

```yaml
vpn:
  image: qmcgaw/gluetun:v3.41.1@sha256:1a5bf4b4820a879cdf8d93d7ef0d2d963af56670c9ebff8981860b6804ebc8ab
  profiles: [egress]
  read_only: true
  cap_drop: [ALL]
  cap_add: [NET_ADMIN]
  devices: ["/dev/net/tun:/dev/net/tun"]
  security_opt: ["no-new-privileges:true"]
  sysctls: { net.ipv4.conf.all.src_valid_mark: "1" }
  tmpfs:
    - /tmp:rw,noexec,nosuid,nodev,size=8m
    - /gluetun:rw,noexec,nosuid,nodev,size=8m
  volumes: ["./vpn/control-auth.toml:/gluetun/auth/config.toml:ro"]
  networks:
    vpn-uplink: { gw_priority: 100 }
    egress-proxy: {}
  mem_limit: 128m
  memswap_limit: 128m
  cpus: 0.5
  pids_limit: 64
  restart: unless-stopped
  healthcheck:
    test: ["CMD", "/gluetun-entrypoint", "healthcheck"]
    interval: 15s
    timeout: 5s
    retries: 3
    start_period: 30s
  # no ports: nothing is published
```

gluetun runs as root inside the container (it programs iptables); with `cap_drop: [ALL]` plus
`NET_ADMIN` that root has no other capability. If it refuses to start with `NET_ADMIN` alone, the
only acceptable addition is `NET_RAW`, and it needs the owner's approval (he approved `NET_ADMIN`
and `/dev/net/tun` only). If `read_only` breaks it, the implementer reports the exact path it
needs and adds a tmpfs for that path; `read_only: false` is not an option without review.

Profile `egress`: the owner's `.env` sets `COMPOSE_PROFILES=egress`. A fresh clone without a VPN
runs without `vpn`, `collector` and `analyzer`; ingest then keeps its gate closed and every
external feature reports "no egress". The stack is still healthy, and CI needs no VPN.

### 2.4 Networks

| Network | Docker name | `internal` | Members | Notes |
| --- | --- | --- | --- | --- |
| `vpn-uplink` | `sp-vpn` (fixed bridge name) | no | `vpn` only | `enable_icc: false`, masquerading on (needed to reach the endpoint), no IPv6 |
| `egress-proxy` | (project prefix) | **yes** | `vpn`, `ingest`, `collector` | The proxy and control server live here |
| `samples` | (project prefix) | **yes** | `db`, `collector`, `analyzer` | Keeps collector and analyzer away from Redis, ingest and api |
| `egress` | | | | **Removed** |

`ingest`: `[backend, egress-proxy]`. `collector`: `[samples, egress-proxy]`. `analyzer`:
`[samples]`. `api` gains no network; it mounts the quarantine read-only (§7.3).

`vpn` is never on `backend` or `samples`: through the proxy one can reach whatever shares a
network with `vpn`, so it must share networks only with its two clients.

### 2.5 IPv6

The Docker networks have no IPv6. gluetun is expected to drop the IPv6 `/128` address and the `::/0`
allowed range when the container has no IPv6 support (it logs this). Either way no IPv6 packet can
leave: the container has no IPv6 route, and the host rule (§4.4) drops everything from `sp-vpn`
except UDP to the IPv4 endpoint. Acceptance check: logs show the IPv6 address skipped, or
`ip -6 route` inside `vpn` lists only `wg0`.

### 3.2 The `suckerpot_egress` package (new, `egress/`)

A small shared package (deps: `httpx`), used by ingest and collector, so the proxy, the gate and the
tests exist once.

```python
class EgressSettings:            # from env, frozen dataclass
    proxy_url: str               # EGRESS_PROXY_URL, default http://vpn:8888
    proxy_user: str              # "egress"
    proxy_password: str          # EGRESS_PROXY_PASSWORD (repr=False)
    control_url: str             # EGRESS_CONTROL_URL, default http://vpn:8000
    echo_urls: tuple[str, ...]   # EGRESS_ECHO_URLS
    allowed_cidrs: tuple[IPv4Network | IPv6Network, ...]  # EGRESS_ALLOWED_CIDRS (or derived)
    check_interval_s: int        # EGRESS_CHECK_INTERVAL_S, default 300

class EgressClosed(Exception): code: str          # "no_vpn", "tunnel_down", "ip_mismatch", ...

@dataclass(frozen=True)
class GateStatus:
    open: bool
    reason: str                  # constant code, never a free-form server answer
    egress_ip: str | None        # the VPN exit address, shown in Settings
    checked_at: datetime

class EgressGate:
    def __init__(self, settings: EgressSettings, *, client: httpx.AsyncClient | None = None): ...
    async def check(self) -> GateStatus           # one self-check (section 3.4)
    async def run(self) -> None                   # check at start, then every interval
    def require_open(self) -> None                # raises EgressClosed
    @property
    def status(self) -> GateStatus

def egress_client(gate: EgressGate, *, timeout: httpx.Timeout, follow_redirects: bool = False,
                  verify: bool = True, limits: httpx.Limits | None = None,
                  headers: Mapping[str, str] | None = None) -> httpx.AsyncClient
    # proxy=settings.proxy_url with auth, trust_env=False, and a transport wrapper that calls
    # gate.require_open() before every request (redirect hops included).

async def open_tunnel(gate: EgressGate, host: str, port: int, *, timeout: float) -> socket.socket
    # CONNECT host:port through the proxy, returns a blocking socket for smtplib.
```

Rules:

- `trust_env=False` always, and **no `HTTP(S)_PROXY` variable is set in compose**. A stray client
  that ignores the factory has neither proxy nor route nor external DNS, so it fails loudly, and the
  static test below catches it before it ships.
- Requests send host names to the proxy (`CONNECT host:443`); ingest and collector never resolve
  external names themselves.
- `EgressClosed` is treated as a retryable "not now" by every worker: no quota is spent, no
  negative cache entry is written.

### 3.3 DNS inside ingest and collector

Both get `dns: ["127.0.0.1"]` like `api`. On internal networks Docker 29's embedded resolver
(127.0.0.11) still answers service names (`db`, `redis`, `vpn`) and does not forward external
names. `just egress-check` proves `getaddrinfo("example.com")` fails in both containers.

Static code test (`ingest/tests/test_egress_static.py`, same idea in `collector/tests/`): AST scan
of the package source; it fails on `httpx.AsyncClient(`, `httpx.Client(`, `socket.create_connection`,
`socket.socket(`, `smtplib.SMTP(` / `SMTP_SSL(`, `urllib.request`, `aiohttp`, `requests`, or
`getaddrinfo` anywhere except in an explicit allow-list (the `smtp` adapter in `alerts/send.py`,
which may only call `open_tunnel`). Test clients built in `tests/` are exempt.

### 3.4 Egress self-check

We do not need to know the home IP, and we must not learn it (learning it means a connection from
it). A **positive** check is stronger than a negative one: the exit IP must be one we expect from the
VPN, and the home IP is never inside the provider's range.

`EgressGate.check()`, in order, stopping at the first failure (gate closed, reason recorded):

1. `GET {control_url}/v1/vpn/status` answers `{"status": "running"}`. Otherwise `tunnel_down`, or
   `no_vpn` if `vpn` is unreachable (profile off, container stopped).
2. `GET {control_url}/v1/publicip/ip` gives gluetun's exit IP `G` (learned through the tunnel).
   Missing: `no_public_ip`.
3. Through the proxy, `GET` each URL in `EGRESS_ECHO_URLS` (default:
   `https://api.ipify.org,https://icanhazip.com`, text body, 64 bytes max, 10 s timeout). At least
   two must answer, and all answers must be the same address `E`. Otherwise `echo_failed` /
   `echo_disagree`.
4. `E == G`. Otherwise `ip_mismatch` (the proxy is not leaving through the tunnel gluetun reports).
5. `E` is a global unicast address (`ipaddress.ip_address(E).is_global`).
6. `E` is inside `EGRESS_ALLOWED_CIDRS`. When that variable is empty, the allow-list is derived:
   `VPN_WG_ENDPOINT_IP/24` for IPv4 (many WireGuard providers exit on, or next to, the server they
   accept on). If the provider exits elsewhere, the gate stays closed with `ip_not_allowed` and
   Settings shows the observed VPN exit address so the owner can set `EGRESS_ALLOWED_CIDRS`.

Cadence: at start, every `EGRESS_CHECK_INTERVAL_S` (default 300 s), and right away after 3
consecutive proxy errors. The gate is closed until the first check passes. Ingest writes the status
to `enrichment_status` (provider `egress`); the collector writes its own row (`egress_collector`).
The event pipeline never waits for the gate: events are stored, only lookups wait.

Rejected alternative: a salted hash of the home IP in `.env` as a deny-list. The home IP is
dynamic, the hash adds nothing over plain text inside `.env`, and a deny-list misses any other
non-VPN path.

## 4. Guardrails and tests

### 4.1 Static compose test (`scripts/guardrails/`)

A small Python package (`pyyaml`, `pytest`) added to the `packages` list in the `justfile` and to
the CI `python` job, so it runs in `just test` and `just check`. Also `just guardrails` alone.
It loads `docker-compose.yml` with `yaml.safe_load` (merge keys resolved), plus each overlay
(`docker-compose.ci.yml`, `docker-compose.it.yml`) merged on top, and asserts:

1. Every network is `internal: true`, except exactly: `ingress` (name `sp-ingress`, masquerade
   off, icc off), `dashboard` (name `sp-dashboard`, masquerade off) and `vpn-uplink` (name
   `sp-vpn`, icc off).
2. `ingress` members are exactly the `sensor-*` services; `dashboard` only `api`; `vpn-uplink`
   only `vpn`; `egress-proxy` exactly `{vpn, ingest, collector}`; no network named `egress`.
3. `ingest`, `collector`, `analyzer` are only on internal networks and have `dns: ["127.0.0.1"]`.
4. `vpn` is on exactly `{vpn-uplink, egress-proxy}`, `cap_add == ["NET_ADMIN"]`, `devices` is
   exactly `/dev/net/tun`, `cap_drop: [ALL]`, `no-new-privileges`, no `ports`, image pinned by
   digest.
5. No other service has `cap_add`, `devices`, `privileged`, `pid: host`, `ipc: host`, or any
   `network_mode` (host, `service:*`, `container:*`).
6. No service except sensors and `api` has `ports`; no service sets `HTTP_PROXY`, `HTTPS_PROXY`,
   `ALL_PROXY` or `NO_PROXY`.
7. `analyzer` mounts `quarantine` read-only; `api` mounts it read-only; only `collector` writes it.

Unit tests of the checker itself feed it small broken compose snippets (one per rule).

### 4.2 Live check: `just egress-check`

`scripts/egress-check.sh` runs on the live stack (profile `egress` up) and prints PASS/FAIL per
line; exit code non-zero on any FAIL. It runs `python -m suckerpot_egress.selftest` inside `ingest`
and `collector` (the module ships with the package, no test tooling in images):

| Check | Expected |
| --- | --- |
| Direct TCP to `1.1.1.1:443` and `9.9.9.9:443` (3 s timeout) | fails (no route / unreachable) |
| UDP DNS query to `1.1.1.1:53` | no answer |
| `getaddrinfo("example.com")` | fails |
| Gate check (§3.4) | open, `E == G`, `E` in the allow-list |
| Through the proxy, `CONNECT` to the `sp-vpn` gateway on the dashboard port, and to `vpn:8000` by an RFC 1918 literal | refused or timed out |
| Through the proxy, a name that resolves to 127.0.0.1 (a public "localhost" test domain set in the script) | refused (rebinding protection) |
| In `analyzer`: direct TCP to `1.1.1.1:443`, and `vpn:8888` | both fail (no route, no such host) |
| `docker compose exec vpn ip link set wg0 down`, then an echo through the proxy within 2 s | fails; gate closes on next check |
| Wait for gluetun to restore the tunnel (≤ 60 s), then gate check | open again |
| `docker compose stop vpn`, then gate check in ingest | `no_vpn`, ingest stays healthy, events still stored; then `docker compose start vpn` |

The script never prints the exit IP in full: it prints `in allow-list: yes/no`.

### 4.3 Kill switch tests

Covered by the last three rows above (tunnel down, container stopped) plus unit tests in
`egress/tests/` with a fake control server and fake proxy: every gate failure reason closes the
gate, the client factory raises `EgressClosed` with the gate closed, and a redirect hop is checked

### 4.4 Host firewall (`scripts/host/firewall.nft`)

The owner applies it himself. New defines and rules (bridge matched by name, like the others):

```text
# The VPN server (from VPN_WG_ENDPOINT in .env). The vpn container may send only this.
define VPN_ENDPOINT_IP = CHANGE_ME          # e.g. 203.0.113.10
define VPN_ENDPOINT_PORT = CHANGE_ME        # e.g. 51820

chain input {
  ...
  # (4) The vpn container never talks to the host.
  iifname "sp-vpn" ct state new counter drop
}

chain forward {
  ...
  # (5) From the vpn uplink, only WireGuard to the one endpoint. Everything else (other hosts,
  #     the LAN, IPv6, TCP) is dropped, even if gluetun's own firewall failed.
  iifname "sp-vpn" ct state new ip daddr $VPN_ENDPOINT_IP udp dport $VPN_ENDPOINT_PORT accept
  iifname "sp-vpn" ct state new counter drop
}
```

This makes the kill switch independent of gluetun: with the tunnel down, the only packet that may
leave is a WireGuard handshake to the endpoint. `scripts/host/README.md` gets the verification
commands (`nft list table inet suckerpot_host`, counters after `just egress-check`).

## 5. Collector

### 5.1 Placement

Two new services built from one image (`collector/`), with different commands, roles and networks:

| Service | Command | Networks | DB role | Quarantine | Why |
| --- | --- | --- | --- | --- | --- |
| `collector` | `python -m collector fetch` | `samples`, `egress-proxy` | `suckerpot_collector` | rw | Talks to the internet through the proxy; never parses content beyond hashing |
| `analyzer` | `python -m collector analyze` | `samples` | `suckerpot_analyzer` | ro | Parses hostile files; has **no** path to the internet or Redis |

Not inside ingest: a bug in a fetcher or parser must not reach Redis, the events pipeline or the
ingest DB role. Splitting fetch from analysis means a parser exploit gets neither the proxy nor
the network. Cost: two small Python containers (~60 MB each idle).

Both are in profile `egress`, `<<: *hardening`, user `10001:10001`, `dns: ["127.0.0.1"]`, tmpfs
`/tmp:rw,noexec,nosuid,nodev,size=16m`. Limits: collector `mem_limit: 256m`, `cpus: 0.5`,
`pids_limit: 32`; analyzer `mem_limit: 512m` (child is capped at 384 MB), `cpus: 0.5`,
`pids_limit: 16`. `collector` depends on `vpn` (`service_started`) and `migrate`; `ingest` does
**not** depend on `vpn`, so the event pipeline never waits for the tunnel.

### 5.2 Input and queue

Download URLs are already stored by ingest as `indicators` rows with `type = 'url'` and
`role = 'download_host'` (from `download_attempt` events and URLs in commands), linked to sessions
through `indicator_sessions`. The collector polls them; it does not read Redis, so the
single-consumer invariant of ingest is untouched.

Every `COLLECTOR_POLL_S` (default 15 s): insert into `fetch_targets` every such indicator with
`demo = false` that is not there yet (`ON CONFLICT (url) DO NOTHING`), then pick due targets
(`next_attempt_at <= now()`, ordered by `next_attempt_at`). URLs found in fetched scripts
(§6.3) are inserted by the analyzer with `depth = parent depth + 1`, only if
`depth <= COLLECTOR_MAX_DEPTH` (default 2) and at most 20 per sample.

Schemes: `http` and `https` are fetched. `tftp` and `ftp` are recorded with status `unsupported`.
**TFTP is deferred**: it is UDP, which cannot cross an HTTP proxy; supporting it means a tiny TFTP
client in the VPN namespace (`network_mode: service:vpn`), a second process sharing the namespace
of the one container with `NET_ADMIN`, and an exception in the guardrails. Not worth it for M21;
the UI says "TFTP: recorded, not fetched".

Re-fetch policy (`url` is unique after normalisation: lower-case scheme and host, default port
removed, fragment dropped, max 1,024 characters):

- Success: re-fetch only if the indicator was seen again after the last fetch and the last fetch
  is older than `COLLECTOR_REFETCH_HOURS` (default 24), at most 7 times. Payloads behind a URL
  rotate, so a new hash on re-fetch is a new sample linked to the same target.
- Failure (network, 5xx, timeout): retry after 15 min, 1 h, 6 h, then status `failed`.
- 4xx, refused URL, too large: final (`gone`, `refused`, `too_large`).

### 5.3 URL validation (SSRF)

Checked before the first request and again on every redirect hop:

- Scheme `http` or `https`; port 1 to 65535; no user-info (`user:pass@`).
- Host is an IP literal: parsed strictly (only canonical dotted quad or bracketed IPv6; decimal,
  octal, hex and short forms such as `http://3232235777/` are refused). Must be `is_global` and
  not in: RFC 1918, 100.64.0.0/10, loopback, link-local, multicast, reserved, the documentation
  ranges, 198.18.0.0/15, the IPv6 ULA and documentation prefixes, `VPN_WG_DNS`, the VPN endpoint,
  and `COLLECTOR_DENY_CIDRS` (owner's own ranges, optional).
- Host is a name: valid IDNA, at least two labels, not `localhost`, not ending in `.local`,
  `.localhost`, `.internal`, `.lan`, `.home.arpa`, `.arpa`, and not one of `API_ALLOWED_HOSTS`
  (the deployment's own names). Single-label names (Docker service names) are refused.
- The name is resolved by gluetun inside the tunnel. Its DNS rebinding protection drops private
  answers, and the host rule drops anything from `sp-vpn` that is not WireGuard, so a name that
  points at the LAN or the host cannot be reached even if the validator missed it.

### 5.4 Fetch limits and client identity

| Limit | Default | Variable |
| --- | --- | --- |
| Max body | 16 MiB, counted on raw bytes as they stream; `Content-Length` is not trusted | `COLLECTOR_MAX_BYTES` |
| Connect / total time | 10 s / 60 s | `COLLECTOR_CONNECT_TIMEOUT_S`, `COLLECTOR_TIMEOUT_S` |
| Redirects | 3, followed by hand, each hop validated | `COLLECTOR_MAX_REDIRECTS` |
| Concurrency | 2 global, 1 per host | `COLLECTOR_CONCURRENCY` |
| Per-host spacing | 10 s between requests to one host | `COLLECTOR_HOST_INTERVAL_S` |
| Global rate | 60 fetches per hour, 500 per day (hard quota in `enrichment_quota`, provider `collector`) | `COLLECTOR_HOURLY_QUOTA`, `COLLECTOR_DAILY_QUOTA` |

- `Accept-Encoding: identity`, body read with `aiter_raw()`: httpx never decompresses, so no gzip
  bomb in the fetcher. A response with a `Content-Encoding` is stored as received.
- `verify=False` for HTTPS: malware hosts often have broken certificates; integrity is not a
  concern for hostile content, and the request goes through the tunnel either way.
- No cookies, no `Referer`, `Accept: */*`. `User-Agent` chosen from the URL: a file name with an
  IoT architecture suffix (`arm`, `arm5`, `arm6`, `arm7`, `mips`, `mpsl`, `m68k`, `ppc`, `sh4`,
  `spc`, `x86`, `i686`) or a `/bins/` path gets BusyBox's `Wget`; any other URL gets
  `Wget/1.21.4`; a `.ps1` or `.exe` gets `Mozilla/5.0 (Windows NT 10.0; Win64; x64)
  WindowsPowerShell/5.1`. The table lives in `collector/collector/identity.py`. Never the project
  name, never a contact address.
- Every attempt is recorded in `fetch_attempts` with a constant outcome code; response bodies of
  failures are not stored.

### 5.5 Quarantine

Volume `quarantine`, mounted at `/quarantine` (collector rw, analyzer and api ro).

```
/quarantine/
  .incoming/                       # temp files, same filesystem, wiped at start
  ab/cd/abcd…<64 hex sha256>       # two-level fan-out; no extension, ever
```

- Write: `os.open(.incoming/<random>, O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW, 0o600)`, hash
  (sha256) while streaming, abort and unlink past the size cap, `fsync`, `fchmod(0o400)`, then
  `os.link`/`rename` to the final path. If the final path exists, the temp file is deleted
  (dedupe). Directories 0o700. No file ever has an execute bit; a static test forbids `chmod`
  with any `x` bit and any `exec*`/`spawn*` call taking a quarantine path.
- `noexec`: a named volume cannot carry mount flags without a host path. Defence in depth instead:
  0400 files, read-only root filesystems, nothing ever passes a quarantine path to an exec call.
  Optional (owner, host side): bind the volume to a host directory with
  `o: bind,noexec,nosuid,nodev`.
- Total cap `QUARANTINE_MAX_MB` (default 2,048): before a fetch, the collector compares the sum of
  `samples.size` where `stored` with the cap; at 100 % it stops fetching (`quarantine_full` in
  Settings) but keeps recording URLs.
- Retention `QUARANTINE_RETENTION_DAYS` (default 90) after `last_seen`: the file is deleted, the
  `samples` row and its analysis are kept forever with `stored = false`. `fetch_attempts` older
  than 90 days are deleted by the same job.
- Never committed (`.gitignore` already excludes volumes; the guardrail test also fails on any file
  under the repo whose name is a 64-hex string).

## 6. Static analysis (never execute)

### 6.1 Library: `analysis/suckerpot_analysis` (new package, pure functions)

No network, no DB, no file system writes. Input is `bytes`, output is a pydantic model.

```python
def analyze(data: bytes, *, rules: CompiledRules, limits: Limits = Limits()) -> AnalysisResult
def compile_rules(directory: Path) -> CompiledRules
def identify(data: bytes) -> FileInfo          # kind, arch, bits, endian, linking, packer
def digests(data: bytes) -> Digests            # sha256, sha1, md5, tlsh | None
def printable_strings(data: bytes, *, min_len: int = 6, max_count: int = 500) -> list[str]
def deobfuscate_shell(text: str, *, max_passes: int = 5, max_out: int = 256 * 1024) -> Deobfuscation
def extract_iocs(texts: Iterable[str]) -> list[Ioc]   # urls, ip:port, domains, with a "where" tag
```

| Feature | Choice | Why |
| --- | --- | --- |
| File type and arch | Own header parsers (~200 lines): ELF (class, endianness, `e_machine` to x86 / x86-64 / ARM / AArch64 / MIPS / PowerPC / SPARC / m68k / SuperH / ARC, static vs dynamic via `PT_INTERP`, stripped via `.symtab`), PE (machine, 32/64, DLL), Mach-O, shebang and shell heuristics, archive magics (gzip, zip, tar, xz, 7z, bzip2), UPX marker | libmagic is a large C parser with its own CVE history and a system dependency; we need a few fields, read with `struct` from bounded offsets. Every offset is checked against `len(data)` |
| Hashes | `hashlib` sha256, sha1, md5; **TLSH** via `py-tlsh` (pinned) | No cp313 wheel exists for `py-tlsh`; it builds from source in the builder stage (`g++`), only the built wheel reaches the runtime image. If the import fails, `tlsh` is `null`, nothing else breaks |
| Strings | Own scanner: ASCII and UTF-16LE runs ≥ 6, first 500 unique, 120 chars each, scan the first 16 MiB | Bounded, no dependency |
| YARA | **`yara-x`** (1.22.1, cp313 manylinux wheel verified) | Rust engine (memory safe), built-in scan timeout. Rules in `collector/rules/yara/*.yar`, compiled once at analyzer start; a broken rule fails the start, not a scan |
| Archives | Identified, **not** extracted in M21 | No decompression bombs. Single-stream gzip extraction with an output cap may come later |
| Packers | UPX detected and reported, never unpacked | Unpacking is execution-adjacent |

YARA rules shipped (written for this repo, MIT, each with `meta: author, description, reference`):
`mirai.yar` (table strings, attack vector names, `/bin/busybox` + ECCHI-style markers), `gafgyt.yar`,
`miners.yar` (XMRig pool and config strings, stratum URLs), `redis_module.yar` (ELF exporting
`RedisModule_OnLoad`, rogue-server module names), `shell_dropper.yar` (multi-arch download loops,
`chmod 777` + run + `rm`), `kinsing.yar`. A hit gives a `family` and tags. **No real malware is
committed for tests**: tests use synthetic buffers (crafted ELF headers, strings assembled in the
test) built at test time.

### 6.2 Shell deobfuscation

For samples identified as text and ≤ 1 MiB. Pure string rewriting, iterated until stable (max 5
passes, output capped at 256 KiB):

- `echo|printf <b64> | base64 -d [| sh|bash]` and `base64 --decode <<< …`: decode, inline the result.
- `printf '\x41\101'`, `echo -e '\x41'`, `$'\x41'`: decode escapes.
- `VAR=literal` then `$VAR` / `${VAR}`: substitute literal values only (quoted or bare words). No
  command substitution, arithmetic or `eval` is ever evaluated; `eval "…"` is unwrapped textually.
- Adjacent quoted pieces (`'ht''tp'`) are joined.

Each rewrite is recorded (`steps: [{"kind": "base64", "count": 2}, …]`) and the final text is
stored. The UI shows it as plain text only.

### 6.3 IOC and C2 extraction

From deobfuscated scripts: URLs (`http`, `https`, `tftp`, `ftp`) become `next_url` links; `http(s)`
ones go back to `fetch_targets` within the depth cap. From binary strings: `ip:port` pairs and
public IPv4 literals, plus host names matching a bounded domain regex with a TLD in a fixed list.
A best-effort Mirai table decoder tries single-byte XOR (keys `0x22`, `0x37`, `0x54`) on runs of
non-printable bytes and keeps results that look like a host name. Every IOC carries a source
(`script_url`, `binary_ip_port`, `binary_string`, `mirai_table`) and a confidence (`high` for URLs and
`ip:port` in a YARA-matched binary, `low` otherwise).

Feedback into indicators: `high` IOCs are upserted into `indicators` (`role = 'c2'` for addresses,
existing roles kept on conflict, `UNIQUE (type, value)` already exists) and each sample's sha256 is
upserted as `type = 'hash'`, `trusted = true`. The existing intel worker then looks them up through
the proxy like any other indicator. Private, documentation and own addresses are dropped by the
same filter ingest uses (`INDICATORS_IGNORE`, `API_ALLOWED_HOSTS`).

### 6.4 Parser safety

The analyzer reads the sample (≤ 16 MiB) and hands it to a **child process** for each sample:

- `asyncio.create_subprocess_exec(sys.executable, "-I", "-m", "collector.analysis_child",
  stdin=PIPE, stdout=PIPE, stderr=DEVNULL)`: fixed argv, no shell, the sample arrives on stdin, so
  the child never opens a path. This is the only process spawn in the package; the static test
  allows exactly this call. (CLAUDE.md §5 forbids process spawning in sensors; the analyzer is
  not a sensor and never executes the sample, it isolates our own parsers.)
- First thing in the child: `setrlimit` `RLIMIT_AS` 384 MiB, `RLIMIT_CPU` 30 s, `RLIMIT_FSIZE` 0,
  `RLIMIT_NOFILE` 16, `RLIMIT_CORE` 0. Not `RLIMIT_NPROC` (counted per uid across the host);
  the container's `pids_limit: 16` bounds processes instead.
- Parent: wall-clock timeout 60 s then `kill()`; stdout capped at 2 MiB; the JSON is validated
  against the `AnalysisResult` model, so a confused child cannot write arbitrary rows. A crash,
  timeout or invalid output gives `analysis_status = failed|timeout` with a constant code; the
  analyzer moves on.
- Inside the child: yara-x timeout 10 s; every parser works on `memoryview` slices with explicit
  bounds; ELF/PE section and program header counts capped at 256.
- Fuzz-style tests: truncated headers, huge counts and offsets, 16 MiB of random bytes, a 16 MiB
  single line, deeply nested base64 (each pass bigger), a script that expands a variable into
  itself. Each must return within limits.

## 10. Risks and open questions

1. **Endpoint split**: the owner adds `VPN_WG_ENDPOINT_IP` and `VPN_WG_ENDPOINT_PORT` to `.env`
   (blocks task A's live checks, not its code).
2. **Allow-list**: does the provider exit on the endpoint's /24? If not, the owner sets
   `EGRESS_ALLOWED_CIDRS` after the first run (Settings shows the observed VPN exit on demand).
3. **Capabilities**: if gluetun needs `NET_RAW` besides `NET_ADMIN`, that is a new approval.
4. **gluetun details to verify on v3.41.1**: plain-DNS upstream variable names, `CONNECT` to
   non-443 ports (needed for SMTP 587/465 and odd malware ports), whether the proxy and control
   ports are accepted from `egress-proxy` without `FIREWALL_INPUT_PORTS`, IPv6 address handling.
5. **Attribution**: payload hosts see a VPN address fetching soon after an attack on the honeypot.
   Attackers can correlate and block it; they cannot see the home IP. Accepted.
6. **Alerts**: webhooks lose the address pinning they have today and rely on the official-host list
   plus gluetun's rebinding protection. Accepted, reviewed in the security pass.
7. **TFTP and FTP** are recorded, not fetched, in M21.
8. **CLAUDE.md** says payload fetching is done by ingest with `FETCH_PAYLOADS`; this design moves
   it to `collector` with `COLLECTOR_ENABLED`. Needs the owner's OK to amend.
