A honeypot you can actually read.

SuckerPot is a self-hosted honeypot with a few realistic sensors and one calm dashboard. Every attack is told as a short story, and every IP, country, tag or URL is a click away from the full picture.

Why

One readable dashboard, a few sensors built well.

Most honeypot stacks are a pile of separate tools and panels that nobody wants to open twice. SuckerPot goes the other way: four focused sensors, and one interface that is the product.

Each page starts with a plain-English finding, then shows the evidence. Colour always means something: one hue per sensor, and red only for the severe events. Every filter lives in the URL, so every view can be shared.

Features

Built to be attacked, and built to be understood.

Four realistic sensors

SSH, Telnet, web and RDP. An OpenSSH 9.6 fingerprint with an emulated shell, a BusyBox telnetd with Mirai-style flows, an Apache 2.4.58 and PHP 8.3 stack with PHP2Shell detection (in final security review), and a Windows Server RDP login with username capture. Nothing an attacker types is ever executed.

Story-first interface

Sessions are the unit. Each one reads as a sentence, opens as a timeline, and for SSH and Telnet, replays in a terminal at real speed.

Hardened by default

Non-root, read-only containers with every capability dropped. An internal backend network, one Redis ACL user per sensor, least-privilege database roles, a single admin login (argon2, CSRF protection) and a host firewall template.

Enrichment and tags

GeoIP and ASN from a local DB-IP Lite database (no key needed) or MaxMind, optional AbuseIPDB and GreyNoise reputation, and a declarative YAML rules engine that tags php2shell, mirai, crypto-miner and more. Quotas are enforced, results cached.

Everything is a link

An IP, a country, an ASN, a username or a URL opens the matching filtered view. Filters live in the address bar, so you can share what you see.

One Docker Compose file

Every component is a service. Raw events are kept 90 days and aggregates forever, with compression, a disk guard and one-command backups, so disk usage cannot run away.

The interface

From a list of attacks to a single attacker's evening.

Session timeline on the left, the same list on a phone on the right. Dark and light, desktop and mobile.

Architecture

Sensors can talk to Redis, and to nothing else.

Ingest is the only service allowed outbound, for GeoIP and reputation lookups. The sensors cannot reach the database, the API or the rest of your network.

Quick start

Up in a few commands.

You need Docker with the compose plugin, on a machine or VM you can afford to lose.

# fill .env: replace every change-me (openssl rand -base64 32)
git clone https://github.com/Theroxat/suckerpot.git && cd suckerpot
cp .env.example .env
docker compose up -d --build --wait
# synthetic attacks, so the dashboard is not empty
docker compose --profile tools run --rm demo

SuckerPot is meant to be attacked. Run it on an isolated host, keep nothing that matters on it, and read the go-live checklist in the documentation before exposing anything.
